# hextet M5（UI）实现计划

> 本计划覆盖 spec §8 M5 行的交付。M5 按「独立性 × 可本地验证性」切成三个切片，
> 从最自洽、可编译可测的 `status --tui` 开始；Tauri 桌面壳与 React 前端依赖外部
> 工具链与视觉设计，单独立项，最后做。

**Goal:** 给 hextet 一个不依赖外部 GUI 工具链的交互式状态视图（`status --tui`），
随后是 daemon 内嵌的 axum Web UI，最后是 Tauri 桌面壳 + React 前端（共享同一 Web
构建产物）。视觉设计（design-taste）单独立项打磨，不混进功能实现。

**设计依据:** `docs/superpowers/specs/2026-08-06-hextet-design.md` §8 M5 行、§10 项目结构
（`crates/daemon` 的 axum Web UI/REST + IPC server、`crates/cli` 的 ratatui TUI、
`apps/desktop`、`web/` 的 React 前端）、§11 文档规范。

## 切片 A：`hextet status --tui`（ratatui）

**为什么先做它**：纯 Rust、无外部服务、无桌面工具链，是 M5 唯一能在开发机上
`cargo build` + 无头单测覆盖的切片。它直接复用 daemon 状态读取路径（
`hextet_engine::state` + `hextet_wg::kernel::KernelBackend::status`），把 `status`
命令当前埋在 `run()` 里的报告组装逻辑抽成可复用函数，TUI 与一次性 `status` 共享
同一数据来源，避免两处漂移。

**现状（读 `crates/cli/src/commands/status.rs`）**：`run()` 里内联了「读内核 WG 状态
→ 读 `<state_dir>/state.json` → 拼 `StatusRow`/`StatusReport`」的全过程，且整体
`#[cfg(target_os = "linux")]`。TUI 要做的第一件事就是把这段抽出来。

**交付:**
- `crates/cli/src/commands/status.rs`：抽出 `pub(crate) fn build_report(cfg, backend, now) -> StatusReport`
  （Linux-only），`run()` 的 `--json`/人类表格两条路径都改调它；`--tui` 分支复用同一函数。
- `Args` 加 `#[arg(long)] pub tui: bool`。
- `crates/cli/src/commands/status_tui.rs`（新，`#[cfg(target_os = "linux")]`）：ratatui
  事件循环——每 1s 重读 `build_report`、渲染「daemon 存活头 + peer 表格（name/address/
  endpoint/source/punch/handshake/rx/tx/routes）」，`q`/`Esc`/`Ctrl-C` 退出；raw mode +
  alternate screen，退出时恢复终端（panic 也恢复，用守卫结构）。
- `crates/cli/Cargo.toml`：`[target.'cfg(target_os = "linux")'.dependencies]` 加
  `ratatui` + `crossterm`（普通 semver，不锁死——这两个是稳定生态，与
  `mainline`/`boringtun` 的「有风险才锁」先例不同）。
- `crates/cli/src/main.rs`/`commands/mod.rs`：注册 `status` 已存在，`--tui` 只是 Args
  新 flag，无需新子命令。

**可测性（无头）**：`build_report` 的纯逻辑（daemon freshness、peer 归类、routes 渲染）
全部抽成可测函数（现状已有 `classify`/`daemon_freshness`，补 `build_report` 对
`MockBackend` + 临时 state 文件的分层测试）；ratatui 绘制循环本身**不**单测（需要
TTY，documented），只做「退出键 → 循环返回」这类不依赖绘制的守卫单测（如可行）。

**验收:** `cargo xtask ci` 全绿（含新单测）；`cargo clippy --target x86_64-unknown-linux-gnu
--workspace --all-targets -- -D warnings` 干净（TUI 代码是 Linux-only，靠交叉 target 覆盖）；
`hextet status --tui` 在真机 Linux 上能进入交互视图并 `q` 退出（真机验证项，macOS 开发机
无法跑 TTY 交互，如实标注依赖 CI/真机）。

## 切片 B：axum 内嵌 Web UI（后续）

spec §10：`crates/daemon`（进程壳：tokio 主循环 + axum(Web UI/REST) + IPC server）。
`status --tui` 之后，把同一 `build_report` 数据经 axum REST 暴露，静态托管 `web/` 构建
产物。依赖 `crates/proto`（daemon<->UI 共享 serde 类型）。**不在本切片做**——先等切片 A
落稳，且它引入 `crates/daemon` 这一新 crate，风险面比 TUI 大。

## 切片 C：Tauri 桌面壳 + React 前端（最后）

`apps/desktop`（Tauri 2 薄壳）+ `web/`（React）。需要 Node 工具链 + Tauri CLI，视觉设计
单独立项。**最后做**，且不阻塞 CLI/Web UI 的用户价值。

---

## 风险与缓解（M5 特有）

| 风险 | 缓解 |
|---|---|
| TUI 代码 Linux-only，macOS 开发机测不了交互 | 抽 `build_report` 纯逻辑无头单测；绘制循环靠交叉 target 编译 + 真机/CI 交互验证，如实标注 |
| ratatui/crossterm 与现有 clap/tokio 的版本共存 | 普通 semver，`cargo deny check` 把关许可与 RUSTSEC |
| axum/React/Tauri 引入多工具链与前端构建复杂度 | 切片顺序强制：先 TUI（零外部工具链），再 axum，Tauri/React 最后并单独立项 |
