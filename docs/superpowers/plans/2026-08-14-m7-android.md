# hextet M7（Android）实现计划

> 本计划覆盖 spec §8 M7 行的交付：engine FFI 化（UniFFI）、VpnService 前台服务、
> gotatun 数据面（Mullvad Android 生产同款）、按需连接模式。v1.0 必含。

**设计依据:** `docs/superpowers/specs/2026-08-06-hextet-design.md` §8 M7 / §9 / §10、
ADR-0012（gotatun 数据面已迁移）、`docs/dev/gotatun-migration.md`（数据面 API 地图）。

**前置已就绪（2026-08-14）：**
- gotatun 0.8.1 已作为跨平台数据面落地（`crates/wg-userspace`，ADR-0012）。
- `hextet_engine::daemon` 已支持 `DaemonHandle::spawn` + `shutdown`（进程内运行 + 优雅
  停机），是 Android 在进程内跑 daemon 的关键前置。

---

## 1. 关键架构差异（Android vs 桌面）

- **TUN 设备不是 `tun` crate 开的**：Android 的 TUN fd 由 `VpnService.Builder.establish()`
  返回（Android 系统分配的 fd），不是 `TunDevice::from_name`。gotatun 的 `DeviceBuilder`
  已支持 `with_ip`/`with_ip_pair` 注入自定义 `IpSend`/`IpRecv`——把 VpnService fd 包一层
  `IpSend`/`IpRecv` 适配器即可（这是 gotatun `tun` feature 之外的 Android 专用 transport）。
- **进程内运行**：Android App 就是进程，daemon 经 `DaemonHandle::spawn` 跑在 App 的
  tokio runtime 里，无跨进程状态问题（state.json 在 App 私有目录）。
- **按需连接**：spec 要求「打洞 <1s、无常驻 keepalive 省电」——这是 VpnService 的
  `on-demand` 模式 + 快速握手，属后续优化切片，不在第一片。

## 2. 迁移切片（按独立性 × 可验证性排序）

| 切片 | 状态 | 交付 |

| **D 按需连接 + 省电** | 🔶 keepalive 分级已做 | `[node] keepalive`（默认 25s；`0` = 关闭持久 keepalive，移动端按需连接），`build_device_spec` + gossip 准入 `add_peer` 统一走 `spec::keepalive_opt`。剩：纯 IPv6 路径自动放宽 ~110s（RFC 6092 探测）、握手加速（`<1s` 打洞）、Kotlin `on-demand` 触发 |

## 3. 切片 A 的关键点（本计划先行）

> **2026-08-14 落地记录**：实际实现与本段初稿有两处出入，以下按现实修正——
> ① 用的是 **UDL**（`src/hextet.udl` + `build.rs` 的 `generate_scaffolding`），不是
> `#[uniffi::export]` proc-macro；②「WG 统计进 state.json」的补充切片**已在切片 A 落地**
> （state.json 升到 v7），所以 `status` 直接返回**含 WG 统计**的完整报告，没有单独的
> `daemon_status`。详见 CHANGELOG「hextet-engine-ffi」。

- **FFI 工具**：UniFFI（spec §8 定）。用 **UDL** 定义接口；`uniffi-bindgen` 生成 Kotlin
  绑定（`apps/android` 构建时生成，届时给 `uniffi` 加 `cli` feature）。Rust 侧
  scaffolding 在 macOS 编译 + 单测。
- **FFI 表面**（已实现）：
  - `load_config(path: String) -> String`（打码配置摘要 JSON 或 `{"error":...}`）。
  - `daemon_spawn(path: String) -> String`（`{"handle":u64}` 或错误 JSON；内部存 DaemonHandle）。
  - `daemon_spawn_with_fd(path: String, tun_fd: i32, mtu: u16) -> String`（M7 切片 B：
    Android VpnService fd；非 Unix 返回错误 JSON）。
  - `daemon_shutdown(handle: u64) -> String`（`{}` 或错误 JSON）。
  - `status(path: String) -> String`（`build_report_from_state` → JSON，**含 WG 统计**；
    state.json v7 起 WG 统计已入盘，跨线程/跨进程读不需要进程内后端）。
- **跨线程 status**：由 state.json v7 解决（`build_report_from_state` 不需要后端），
  FFI `status` 与 CLI `hextet status` 的跨进程路径共用同一份 state.json。

## 4. 诚实边界

- **Android 需要 SDK/NDK + Gradle + 真机/模拟器**：本机是 macOS、无 Android SDK，
  切片 B/C/D 无法本机运行时验证；切片 A 的 Rust scaffolding 可本机编译 + 单测，Kotlin
  绑定生成后仅编译检查（无 Android 项目可编译）。切片 B 的 Kotlin 壳已写成（`apps/android/`），
  但**编译验证待有 SDK 的机器**——本仓库不声称 Kotlin 编译通过。
- **配置引导（join/init）走 FFI 已落地（Rust 侧）**：编排逻辑下沉到 `hextet_core::bootstrap`
  （`join_network`/`init_network`），FFI 新增 `join(token, out_dir)`/`init(name, out_dir)`（返回
  结果 JSON 或 `{"error":...}`），Android App 可全自助入网（无需桌面侧预置配置）。**Kotlin 侧
  接线（`HextetClient` 加 `join`/`init` + `MainActivity` 首启流程）是剩余工作**——`apps/android/`
  当前仍只支持预置 `filesDir/hextet.toml` + `node.key`，待把 FFI `join`/`init` 接入首启引导。
- **VpnService 单一槽位**：与代理类 App 冲突（spec §2 诚实边界），文档需给出指引。
- **gotatun 是 pre-1.0**：锁死 `=0.8.1` + `cargo deny` 常开（ADR-0012）。

## 5. 验收（切片 A）

- `cargo test`/`clippy` 本机全绿；UniFFI scaffolding 编译通过；`status`/`daemon_spawn`/
  `shutdown` 的 Rust 单测覆盖（无 root、无真实数据面——`status` 读临时 state.json，
  `daemon_spawn` 用 `MockBackend` 或空后端路径）。
