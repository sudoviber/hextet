# hextet M7（Android）实现计划

> 本计划覆盖 spec §8 M7 行（v1.0 必含）的交付。按「独立性 × 可本地验证性」排序：
> **第一片（FFI 边界，本仓库已落地）** 是纯逻辑 + 零 Android 工具链，可在 macOS 上
> 完整编译验证；gotatun 数据面、VpnService 前台服务、按需连接都依赖 Android NDK / 真机，
> 放到后续片并如实标注「待 Android 工具链」。

**Goal:** Android 客户端（VpnService 前台服务 + gotatun in-process 数据面 + 按需连接），
复用 M7 第一片敲定的 UniFFI 边界；engine 从 M0 起保持 FFI-ready 的承诺在本里程碑兑现。

**设计依据:** `docs/superpowers/specs/2026-08-06-hextet-design.md` §8 M7 行、§9 平台矩阵
（Android：gotatun in-process / VpnService / App 复用 React 前端）、§10 项目结构
（`apps/android/` M7 壳 + UniFFI 绑定、engine「无进程假设，FFI-ready」）、§13 风险
（rustls 默认 aws-lc-rs 交叉编译坑 → 显式 ring provider）；
`docs/adr/ADR-0012-android-ffi-boundary.md`（本里程碑第一片的 FFI 边界 ADR）。

## 切片 A：FFI 边界（UniFFI）——✅ 已完成

**为什么先做它**：纯逻辑、零 Android 工具链、可在 macOS 上完整编译 + 单测验证。它是 M7
其余片的地基——Kotlin 侧调 engine/数据面都经过这条边界，先钉死类型映射与错误映射，
后续片不返工。

**交付**：`crates/core-ffi`（`cdylib` + `lib`），只依赖 `hextet-core`（无 tokio、无平台依赖）。
六个同步函数覆盖 Android 首次启动 onboarding 的最小闭环：生成身份 → 派生前缀/节点地址 →
渲染配置 → 加载/校验配置。错误折叠成扁平 `FfiError`；地址/密钥/路径分别映射为 `String` /
base64 `String` / `String`。详见 ADR-0012 的「现状」审计表与「决策」。

**验收**：`cargo build --workspace --all-targets`、`cargo test --workspace`、
`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all --check` 全绿；
`cargo test -p hextet-core-ffi` 4 个 roundtrip 单测通过。

## 其余切片（依赖 Android 工具链 / 真机，后续做，如实标注）

- **B engine FFI**：ADR-0012 决策 6 已定 runtime 归属策略（宿主拥有 runtime、FFI 只暴露同步
  控制面）。关键点是拆 `daemon::run` 为「纯逻辑 tick + 注入 runtime」，并把
  `lan/gossip/dht/ddns/relay_server/probe_responder` 的 `serve()` 任务生命周期挂到引擎对象、
  受 VpnService 生命周期约束。状态回调若走 UniFFI callback interface，须按 ADR-0012 决策 5
  加收窄 `#![allow(unsafe_code)]`。
- **C gotatun 数据面**：**独立 ADR**（不在 FFI 边界 ADR 内）。要裁决：gotatun MSRV 1.95 是否
  抬工作区 MSRV（动 OpenWrt musl 交叉编译工具链）、默认 `aws-lc-rs` 显式切 `ring` provider
  （spec §13 的交叉编译坑）、pre-1.0 + 审计进行中的取舍（ADR-0007「代价与再评估」触发条件 1/2
  已在监控）。`platform::tun`（ADR-0007 决策 2 预留的 `gotatun::tun` 适配点）如何在 VpnService
  的 fd 上落地也要一起定。
- **D VpnService 壳**：`apps/android/` 项目 + 前台服务 + UniFFI 绑定 Gradle 接线
  （`docs/dev/build.md` 已写 library 模式的 `uniffi-bindgen generate` 命令）。UI 复用 `web/`
  React 前端（WebView 或原生轻壳，spec §9「M7 定」）。
- **E 按需连接**：打洞 <1s + 无常驻 keepalive 省电，依赖 B/C 就位；手机定位是「主动发起方 +
  按需连接」（spec §2）。
- **F 槽位冲突文档**：hextet 在 Android 上占用 VpnService 单一槽位，与 Clash/mihomo 系
  TUN + fake-IP 代理冲突（与 Tailscale 同类）；文档按 spec §5「不接管 DNS、路由仅自有 ULA
  前缀」的既定姿态写 Android 侧指引（家庭场景优先靠路由器组网让手机零客户端）。

## 风险与缓解（M7 特有）

| 风险 | 缓解 |
|---|---|
| gotatun MSRV 1.95 > 工作区 1.85 | 独立 ADR 裁决；不并入 FFI 边界片；ADR-0007 已留「可换 NepTUN/boringtun」后路 |
| rustls 默认 aws-lc-rs 交叉编译坑 | spec §13：显式 ring provider；CI 对每个 Android target 编译验证 |
| VpnService 单一槽位与代理 App 冲突 | 切片 F 文档 + 家庭场景优先路由器组网 |
| 本机（macOS）无法编译 Android 目标 | FFI 片已用「host 编译验证 + 纯 Rust 测试 roundtrip」替代真机验证；真机/NDK 验证留到 B/C 片 |
