# gossip 协议（隧道内签名条目）

> 落地形态见 `docs/adr/ADR-0004-gossip-signed-udp-instead-of-quic.md`。
> 设计出处：`docs/superpowers/specs/2026-08-06-hextet-design.md` §3 D4（控制平面）。

## 1. 定位

gossip 在 WireGuard 隧道内用签名 UDP 报文交换三种**幂等的小状态声明**：

| 类型 | 含义 | 签名者 |
|---|---|---|
| `Endpoint` | 某 node 宣告自己当前可达的地址与 WG 端口 | node **自己** |
| `Member` | 某 node 被准入为成员（带名字、site、invite id） | 管理员/授权节点 |
| `Revocation` | 某 node 被吊销 | 管理员/授权节点 |

隧道内已由 WireGuard 认证加密，所以条目自身不加密、也不做对称 MAC——它只靠
ed25519 签名 + 单调 `seq` 保证「不可伪造」与「分区重连后确定性收敛（LWW）」。

## 2. 传输

- 端口：默认 **4197**（`[node] gossip_port`）。
- **只监听 overlay 地址**：socket 绑定在 `[本节点 overlay 地址]:gossip_port`，隧道外的
  包到达不了这个地址（overlay 是 ULA，只有隧道路由）。作为第二道防线，收到包后仍
  校验**源地址在网络 /48 内**，否则直接丢。
- 发送目标：当前所有已连接 peer 的 overlay 地址（配置里的 peer + 运行时 gossip 准入的
  member）。gossip 只沿已有的隧道边转发——它**不**负责建立新隧道，所以转介的前提是
  「两端都与某个中间节点保持着连接」。
- 节奏：**周期 30s** 全量重发 + **变化即发**（收到新条目、本机条目更新时立刻广播）。
  丢包靠周期重发兜底。

## 3. 线格式

所有多字节字段大端。`sig` 是 ed25519 签名，**签的是它前面的全部字节**（规范编码，
不含 `sig` 本身）。

```
 0     4     5     6     8       14      46      78
+-----+-----+-----+-----+-------+-------+-------+----------------
| HXTG| ver |kind | seq |  node | signer| 载荷… | sig(64)
+-----+-----+-----+-----+-------+-------+-------+----------------
```

- `magic`：`HXTG`（4 字节）。
- `ver`：1。
- `kind`：1 = `Endpoint`，2 = `Member`，3 = `Revocation`。
- `seq`：单调序号（u64，Unix 秒即可，调用方保证单调不减）。
- `node`：主体公钥（32 字节 ed25519）。
- `signer`：签名者公钥（32 字节）。`Endpoint` 恒等于 `node`；`Member`/`Revocation`
  恒不等于 `node`。
- `sig`：64 字节 ed25519，签 `magic..载荷末尾`（不含 sig）。

### 3.1 `Endpoint` 载荷

```
 78      79      81        81+16*n
+-------+-------+-------+--------------+
|addr_n | port  | 地址×n（各 16 字节）
+-------+-------+-------+--------------+
```

- `addr_n`：地址数量（0..=4）。
- `port`：WG 监听端口。
- 地址：IPv6 网络字节序。读取方用 `is_usable_endpoint_addr` 过滤 ULA/链路本地等。

总长 = `78 + 3 + 16*n + 64`。

### 3.2 `Member` 载荷

```
 78      80      81       81+name_len        …+16
+-------+-------+--------+----------------+-------+
| site(2)|name_len| name  | invite_id(16)
+-------+-------+--------+----------------+-------+
```

- `site`：该 node 派生的 16-bit site subnet id。
- `name_len`：u8，名字字节数（≤255）。
- `name`：UTF-8 成员名。
- `invite_id`：关联的一次性 invite token id（16 字节，去重与审计）。

总长 = `78 + 3 + name_len + 16 + 64`。

### 3.3 `Revocation` 载荷

无载荷。总长 = `78 + 64`。

## 4. 校验顺序（decode）

1. 长度下界（≥ 头部 + 签名）。
2. `magic` → `ver` → `kind`。
3. 解析 `node` / `signer` 公钥（曲线点校验）。
4. 按 `kind` 解析载荷并校验**总长精确自洽**（变长报文不接受尾随填充）。
5. **验签**（signer 对规范编码的签名）。
6. **签名者约束**（安全规则，不是可选项）：
   - `Endpoint` 必须 `signer == node`（不能替别人宣告地址）；
   - `Member` / `Revocation` 必须 `signer != node`（不能自己准入/吊销自己）。

## 5. 收敛规则（LWW）

同「主体 node × 类型」只保留一条：`seq` 大者获胜；`seq` 相同时取**规范编码字节序小者**
（保证两个分区最终收敛到同一条目，与到达顺序无关）。

## 6. 安全

| 威胁 | 机制 |
|---|---|
| 伪造某 node 的地址（诱导打洞到攻击者地址） | `Endpoint` 强制自签名 |
| 自准入 | `Member` 禁止 `signer == node` |
| 绕过吊销（自「吊销」自己） | `Revocation` 禁止 `signer == node` |
| 重放旧条目覆盖新条目 | 单调 `seq` + LWW |
| 隧道外窃听/篡改 | 隧道内 WireGuard 认证加密 |
| 隧道外注入 | 源地址必须在网络 /48 内 |
| 表无限膨胀 | 键 = (node, kind)，每 node 每类型一条；能进来的 node 受成员资格约束 |

## 7. 诚实边界

- gossip 不建立隧道：转介只在「两端都与中间节点保持着隧道」时生效。全网同时断连
  （中间节点也不可达）时 gossip 帮不上，那正是会合兜底链 ⑤ DHT 的职责。
- `seq` 的单调性由调用方维护；协议层只按 LWW 收敛，不做绝对时间校验。
